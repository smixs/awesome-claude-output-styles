### Decisions
- Один install.sh с аргументом стиля вместо 17 отдельных скриптов: per-style curl достигается через `bash -s -- <style>`, меньше дублирования. Локальный запуск из чекаута копирует файлы вместо curl (для тестов до пуша).
- Активация: outputStyle берётся из `name:` frontmatter установленного файла (sed), а не из захардкоженной мапы — один источник истины.

- style-maker при нескольких аргументах не активирует ничего (активация только при ровно одном стиле).

- (пока нет)

## 2026-08-07 (третья итерация: нативный формат)

### Decisions
- Причина «выцветания» кастомных стилей в длинных сессиях — не размер файлов: харнесс подкрепляет свои built-in стили каждый ход, кастомные — нет. Формат тела тоже имел значение: файлы читались как документация, а не как директивы.
- Все 19 стилей переведены на формат, в котором Claude Code держит собственные стили: identity-строка («You are an interactive agent that helps users with software engineering tasks. In addition to completing those tasks, you must …») + маркер `# <Name> Style Active` + процедурные правила («In every response: …»). В этом виде харнесс воспринимает стиль как родной.
- Из тел стилей удалено всё human-facing: credits-футеры со ссылками, мета-комментарии, «Before:»-блоки примеров (негативный пример = инъекция нежелательного текста в системный промпт каждой сессии). Тело стиля уходит в системный промпт дословно — каждый лишний байт разбавляет инструкции. Атрибуция переехала в docs/CREDITS.md; README-таблицы уже кредитовали всех.
- Новый enforcement-механизм: hooks/style-reminder.sh (UserPromptSubmit) даёт активному кастомному стилю то же per-turn подкрепление, что имеют built-ins; молчит для default и built-in стилей (не дублируем). install.sh получил флаг `--enforce` (идемпотентная регистрация в settings.json через python3, sed-fallback).
- format-guide: секция «Why the format below works», конвенции #1 (структура built-in), #7 (positive example only), #9 (zero human-facing content). Убрано неточное «Claude Code keeps reminding the model to follow them» — само по себе это верно только для built-ins; с `--enforce` становится верно и для наших.
- style-maker синхронизирован: identity line + Style Active header в шаблоне, positive example only, Step 4 предлагает enforcement-хук.

### Deviations
- Конвенция «before/after examples in the body» (была #6) отменена: противоречила собственной доктрине positive framing. Before/after остаётся в README для людей.

### Gotchas
- install.sh: `set -- "${args[@]}"` на пустом массиве падает под bash 3.2 + set -u; используем `${args[@]+"${args[@]}"}`.
- Тело стиля инжектится дословно, frontmatter — нет. HTML-комментарии в теле тоже уходят в промпт.

### Open questions (решены за пользователя)
- Хук ставится опционально (`--enforce`), не по умолчанию: молча писать hooks в чужой settings.json при установке «просто стиля» — слишком инвазивно.

## 2026-08-16 (четвёртая итерация: бенчмарк-харнес)

Повод: разбор alexgreensh/attention-span (498★ против наших 47★). У них 3 стиля с
воспроизводимым бенчмарком, у нас 19 стилей без единой цифры. Их числа я
пересчитал по их же сырым данным — честные (заявлено 43%, по данным 40.9%).

### Decisions
- Харнес написан с нуля, их код не копировался: attention-span под AGPL-3.0, наш
  репо MIT. Заимствованы идеи (герметичная генерация, разделение «работа» и
  «вывод», отказ от LLM-судьи), не строки.
- Четыре измерения в одном прогоне: work (12 задач со скрытыми тестами), size
  (сокращение символов), shape (форма текста), purity (чистота артефакта).
- Дисковый кэш ответов по ключу (model, style body, prompt, rep). Default-арм
  генерится один раз и переиспользуется всеми 19 стилями — иначе прогон стоит
  вдвое дороже на ровном месте.
- Метрика `claudisms_per_1000w` берёт паттерны из docs/claudisms-2026.md. Список
  фраз внутри metrics.py безопасен: файл измеряет, в системный промпт не уходит.
- Классические reading grades (Flesch-Kincaid) не используются: они видят только
  длину слов и слепы к стене текста — ровно к тому, что стили и лечат.
- Модель по умолчанию `claude-opus-5`: репо продаёт лечение многословия Opus 5,
  мерить надо на нём же. Переопределяется через `BENCH_MODEL`.
- Кэш ответов в .gitignore (2.5 МБ на полный прогон), агрегаты results/*.json
  коммитятся.

### Deviations
- Задачи и вопросы свои, не их набор: и по лицензии, и чтобы прогон не был
  подогнан под их три стиля.

### Gotchas
- Markdown-таблица без фикса считалась одним предложением на 64 слова и забивала
  max_sentence_words и longest_wall_words. prose() теперь вырезает строки таблиц,
  заголовочные решётки и код; _units() режет прозу на единицы, которые предложение
  не пересекает (буллет без точки — своя единица).
- Промпт подаётся в `claude -p` через stdin: `--disallowedTools` вариадический и
  съедает позиционный аргумент.
- Герметичность проверена эмпирически: под `--setting-sources ""` ответ приходит
  на английском и без мата, то есть глобальные CLAUDE.md и output style не текут
  в арм.
- Первый кейс slugify требовал транслитерации юникода — этого не было в промпте,
  и оба арма валились бы одинаково. Заменён: бенчмарк меряет стиль, а не угадывание
  недосказанной спеки.
- Тесты проверены мутациями (пустой код, наивные реализации) — ловят.

### Открытая находка
- `words_to_first_anchor` у wait-what 98 и plain-english 80 против 36 у дефолта.
  Прозаические стили сканируются хуже голого Claude. Это реальный трейд-офф, в
  README его надо назвать, а не прятать.

### Open questions (решены за пользователя)
- Полный прогон 19 стилей платный (~800 генераций на Opus 5), поэтому пилот сделан
  на 3 стилях с `--limit 4`, а масштаб выносится на решение Сергея.

## 2026-08-16 (пятая итерация: отказные режимы ограничений)

Повод: разбор attention-span показал, что их правила покрывают случаи, где
соблюдение ограничения делает ответ хуже. У наших 19 стилей этого не было.

### Decisions
- Во все 19 стилей добавлены три правила, каждое сформулировано голосом стиля,
  не копипастой: (1) запрос глубины отменяет бюджет длины и шаблон, (2) артефакт
  выдаётся голым, персона внутрь артефакта не лезет, (3) scoped-условия и числа
  не расширяются и не округляются.
- Конвенция #11 в format-guide.md: «покрой отказные режимы своего же
  ограничения». style-maker обновлён — генерируемые стили получают то же.
- Правило про «предупреждение режется последним» осталось только в format-guide
  и style-maker: в телах стилей его роль уже играет блок Guardrails.

### Deviations
- Механической вставки одного абзаца в 19 файлов не делал: caveman получил правило
  на языке caveman, yoda — про «артефакт мудрости не несёт», thing-explainer —
  простыми словами. Одинаковый текст в разных голосах читался бы как чужеродная
  вставка и разбавлял бы сам стиль.

### Gotchas
- Детектор чистоты артефакта (`is_pure`) ложнил: искал признаки обёртки внутри
  fenced-блока, то есть внутри самого артефакта. Коммит-месседж со строкой
  «as follows:» считался обёрнутым. Починено: блок — это артефакт, проверяется
  только рама вокруг него; пустая рама = чисто.
- Проверено на живых генерациях: голый Opus 5 даёт 1/8 чистых артефактов;
  adhd 6/8, plain-english 8/8, yoda 5/8, caveman 6/8.
- Пилотные results/*.json удалены: снимались старым детектором и старыми
  стилями, в репо их держать — вводить в заблуждение.
